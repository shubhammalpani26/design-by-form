# Nyzora MCP Tool Builder

## Context

Nyzora exposes an OAuth-protected MCP server built with `@lovable.dev/mcp-js`. The server definition is at `src/lib/mcp/index.ts`. Individual tools live in `src/lib/mcp/tools/`. The Supabase client factory is in `src/lib/mcp/supabase.ts`.

## Adding a tool

1. Create a new file under `src/lib/mcp/tools/<tool-name>.ts`.
2. Default-export a `defineTool` result from `@lovable.dev/mcp-js`.
3. Use Zod for `inputSchema`. Keep schemas small and avoid runtime enums from unbounded data.
4. Set accurate `title`, `description`, and `annotations` (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`).
5. For authenticated tools, import `supabaseForUser(ctx)` from `../supabase` and call it inside the handler. Never take `user_id` from tool input or return/log the bearer token.
6. For public/anonymous tools, use `supabaseAnon()` from the same factory. Public tools must not bypass RLS.
7. Import the tool into `src/lib/mcp/index.ts` and add it to the `tools` array.

## Validation and deployment

1. After editing, run `app_mcp_server--extract_mcp_manifest` to regenerate `.lovable/mcp/manifest.json`.
2. If extraction fails, fix the entry and rerun before deploying.
3. Deploy the `mcp` edge function with `supabase--deploy_edge_functions` (`function_names: ["mcp"]`).
4. Do not hand-edit `supabase/functions/mcp/index.ts`; it is auto-generated by the Vite plugin.

## Security invariants

- All tool handlers must be import-safe: no env reads, I/O, or throws at module top level.
- Never reference `SUPABASE_SERVICE_ROLE_KEY` in tool code.
- Keep the OAuth issuer as `https://<projectRef>.supabase.co/auth/v1` where `projectRef` is read from `import.meta.env.VITE_SUPABASE_PROJECT_ID`.
- Do not leak OAuth tokens into the model context or browser UI.

## Memory (learns from feedback)

This agent shares the `public.agent_learnings` memory table (admin-only).

**Read first.** Before answering, load standing rules with the Supabase read query tool:

```sql
SELECT kind, topic, feedback, learning, weight
FROM public.agent_learnings
WHERE active = true AND skill IN ('nyzora-mcp-tool-builder', 'ceo-orchestrator')
ORDER BY weight DESC, created_at DESC
LIMIT 30;
```

Treat every row as binding: never re-propose something recorded as rejected, always apply recorded preferences, and prefer the higher `weight` when rows conflict.

**Write after feedback.** When Shubham corrects, rejects, approves, or states a preference, insert a row immediately with the Supabase insert tool — `skill = 'nyzora-mcp-tool-builder'`, `kind` one of `feedback` | `preference` | `decision` | `metric`, `context` = what was proposed, `learning` = the rule to apply next time, `weight` 5 for explicit corrections, 4 for preferences, 3 default. When a new rule contradicts an old one, set the old row `active = false` instead of duplicating. Never store secrets or bank details. Confirm each write in one line ("Noted: …").
