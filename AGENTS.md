# Project architecture

- Keep product-specific editorial comparisons in the product page and upload guidance beside the upload control, so merchandising does not alter preview generation or checkout behavior.
- On photo-based Originals pages, show upload before optional personalization controls; why: visitors can start with their photo without losing access to lettering and colour choices.
- Originals lettering goes only on the plinth's flat front wall and fails into manual review if off-centre, off the flat face, or too small; why: lopsided/faint lettering must never ship silently.
- A daily read-only watchdog flags paid Originals orders that miss schedule and emails one digest; why: partner failures must never be discovered by chance, and the watchdog must never act on orders itself.
- The Originals geometry gate (supabase/functions/_shared/meshCheck.ts) must flag thin features (wings, ears, tails, raised paws under ~1.4 mm) via surface sampling, not just mean wall thickness; why: Slant accepts the slice but fails thin features at QC and cancels the paid order days later (TAM order, Oct 2026).
- Originals print files must carry exactly one base: the generated plinth is cut (flat ledge, neck, or straight-sided block via `_shared/plinthProfile.ts`) before ours is added, and `findStackedPlinth` refuses/holds any file with a second block on our base (order hold in originals-model, hard stop in originals-fulfill); why: a missed filleted plinth got a second base slid under it and shipped with two names (Hampton order, Oct 2026).
- A stacked file is rebuilt from the file itself first (`_shared/restackPlinth.ts`), generator mesh only as fallback, and an order pass that rebuilds a base stops there and hands lettering/sending to a fresh pass; why: generator tasks expire, and rebuild + engraving in one worker exceeds its memory limit.
- The lettered name always comes from the stored heading, and a revision that renames the pet updates that heading (`_shared/revisionName.ts`); why: the render and the print file must never show different names.
- Exterior-surface checks must use spatially indexed signed ray crossings, not a full-mesh winding calculation per sample; why: overlapping internal shells must be excluded without exhausting the order-check worker's CPU budget.
- Mesh repair retries apply only to repairable topology blockers and reuse their measured report; why: welding cannot fix thin material and repeated analysis can exhaust CPU before returning a safe rejection.
- Originals previews screen each upload before rendering and reject photos with no pet or explicit content; why: the product is pets-only and an explicit upload reached a partner (TAM, Oct 2026). The screen fails open so outages never block shoppers; preview approval still gates production.
- When the Originals photo screen cannot run, the preview is stored as unscreened and any order from it is held for admin review (with email); why: fail-open must never let an unchecked photo reach the partner.
- Meta Conversions API events reuse the pixel event_id (Purchase = first order row id, sent once from markOriginalsPaid; InitiateCheckout via meta-capi relay) and are sent only when the browser had tracking consent at checkout; why: Meta dedupes browser+server copies and no-consent visitors must never be reported.
- Admin dashboard Meta ad reads go through the linked Meta Ads connector gateway, not stored Graph API tokens; why: pasted Meta tokens expire after ~60 days and silently broke the dashboard (Oct 2026).
- Social carousels store ordered slide URLs in `social_scheduled_posts.media_urls` (cover also in `image_url`) and publish via Instagram child containers / Facebook unpublished photos + one feed post; why: one scheduler path serves singles, Reels and carousels, and `dry_run` lets admins prove Meta accepts a post without publishing it.
- Buyer-facing Originals prices come only from `retailFor` in `supabase/functions/_shared/originalsPricing.ts`; SKUs in `FIXED_PRICE_SKUS` always charge their PRICE_BOOK list price (cached and stored quotes included), and partner slices only prove printability and record cost; why: ads promise list prices and live quotes silently showed higher ones after the preview.
- Ad-campaign attribution lives in `supabase/functions/_shared/adCampaigns.ts` (one campaign per visitor, last specific ad touch; untagged Meta links recognised by landing page) and the client stores the latest ad touch in `nyz_ad_touch` for 30 days; why: the dashboard must credit previews/checkouts to the right campaign even when an ad link carries no utm_campaign.
- Catalog studio photos are AI *edits* of each product's own photo (admin-product-studio-photo), stored in `designer_products.studio_image_url` beside the untouched `image_url`; pages and cart prefer the studio photo and Shopify gets it as first media; why: shoppers see a clean consistent shot without the piece's shape changing, and the original stays restorable. Originals pet pages keep real finished-piece photos only.
- Files uploaded to Slant are named with a content-hash suffix (`partnerFileName` in `_shared/slant3d.ts`); why: Slant overwrites files with the same name in place, so a re-upload could silently change the file on an order that is already placed.
